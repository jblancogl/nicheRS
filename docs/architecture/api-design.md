# NicheRS REST API v1 — design

Status: draft · Date: 2026-10-15 · Rationale: `docs/research/11-backend-architecture.md`
(references [n] below point to that document's reference list / `docs/research/refs/11.md`).

## 1. Scope

Contract between the NicheRS server (single Rust binary) and its clients (embedded React UI, CLI,
scripts). Covers resources, JSON schemas, status codes, errors, pagination, idempotency, SSE event
types and versioning. Normative keywords MUST/SHOULD/MAY as in RFC 2119. The machine-readable source
of truth is the OpenAPI 3.1 document generated by utoipa and served at `GET /api/v1/openapi.json`
[REC]; this document is the human design reference and must not contradict it.

## 2. Conventions

| Topic | Rule |
|---|---|
| Base path | `/api/v1` |
| Media types | requests/responses `application/json; charset=utf-8`; errors `application/problem+json` (RFC 9457 [20]); events `text/event-stream`; artifacts their own type (`image/tiff; application=geotiff; profile=cloud-optimized`, `text/csv`, `image/png`, `application/geo+json`, `application/zip`) |
| Field naming | `snake_case` |
| IDs | UUIDv7 strings (`"0192f3a4-…"`), prefixed by nothing; artifact ids are content hashes `"blake3:<64 hex>"` |
| Timestamps | RFC 3339 UTC, ms precision (`"2026-10-15T09:12:03.120Z"`) |
| Numbers | areas in km² (`f64`), resolutions in CRS units with explicit `crs`; probabilities 0..1 |
| CRS | every geometry/raster carries `crs` as `"EPSG:<code>"`; GeoJSON input is EPSG:4326 per RFC 7946 [UNVERIFIED – prior knowledge] |
| Unknown fields | clients MUST ignore unknown response fields and unknown SSE event types; server rejects unknown request fields (`400 invalid-request`) to catch typos in scientific parameters |
| Request id | server sets `X-Request-Id` on every response (accepts client-provided value) |
| Auth | none in v1 single-user mode; reserved: `Authorization: Bearer` → 401/403 problem types |
| Body limit | 10 MiB JSON (study-area GeoJSON); larger uploads via `POST /datasets` multipart (configurable) |

### 2.1 Pagination

Cursor-based for all list endpoints.

```
GET /api/v1/jobs?limit=50&cursor=eyJ...&state=running&sort=-created_at
200 { "items": [...], "next_cursor": "eyJ..." | null }
```

- `limit` 1..200, default 50. `cursor` is opaque (base64url of `(sort_key, id)`); stable under inserts
  because ids are time-ordered.
- No total count by default; `?include=total` MAY return `"total"` (costly).
- `Link: <...>; rel="next"` header mirrors `next_cursor`.

### 2.2 Idempotency

`POST /jobs`, `POST /batches`, `POST /datasets`, `POST /study-areas` accept
`Idempotency-Key: <1..255 visible ASCII>` (recommended: UUID). Semantics follow
draft-ietf-httpapi-idempotency-key-header-07 [15] (expired draft; this is NicheRS's own contract):

| Situation | Response |
|---|---|
| First request | normal (e.g. 201); key stored 24 h with request fingerprint (BLAKE3 of canonical body) |
| Replay, same fingerprint, completed | original status + body, header `Idempotent-Replayed: true` |
| Replay, same key, different fingerprint | `422` problem `idempotency-key-reused` |
| Replay while original still processing | `409` problem `idempotency-request-in-progress` |

Domain-level dedup: `job.spec_hash` (§4.1). With `"reuse": "if_identical"` the server returns an
existing `succeeded` job with the same `spec_hash` (`200`, `Content-Location: /api/v1/jobs/{id}`)
instead of creating one.

### 2.3 Errors (RFC 9457)

```json
{
  "type": "https://nichers.dev/problems/validation-failed",
  "title": "Request validation failed",
  "status": 422,
  "detail": "2 fields are invalid.",
  "instance": "/api/v1/jobs",
  "code": "validation-failed",
  "request_id": "0192f3a4-7c1e-7a10-9d2b-5b8e0c1f2a33",
  "errors": [
    { "pointer": "/species/0/taxon_key", "detail": "unknown GBIF taxon key 999999999" },
    { "pointer": "/model/maxent/regularization_multiplier", "detail": "must be > 0" }
  ]
}
```

Problem catalogue (`code` = last path segment of `type`):

| code | status | When |
|---|---|---|
| `invalid-request` | 400 | malformed JSON, unknown field, bad query param |
| `idempotency-key-missing` | 400 | only if server configured to require it |
| `unauthorized` / `forbidden` | 401 / 403 | reserved |
| `not-found` | 404 | unknown id |
| `method-not-allowed` | 405 | |
| `not-acceptable` | 406 | e.g. events endpoint without `text/event-stream` acceptable |
| `conflict-state` | 409 | invalid state transition, e.g. results of a running job (cancelling a finished job is not an error, see §4.4) |
| `idempotency-request-in-progress` | 409 | |
| `gone` | 410 | artifact garbage-collected |
| `payload-too-large` | 413 | |
| `unsupported-media-type` | 415 | |
| `validation-failed` | 422 | semantic validation; `errors[]` with JSON Pointers |
| `idempotency-key-reused` | 422 | |
| `resource-limit-exceeded` | 422 | job estimate > configured memory/CPU budget; extensions `estimated_memory_mib`, `budget_mib` |
| `rate-limited` | 429 | with `Retry-After` |
| `internal` | 500 | unexpected; detail generic, see logs by `request_id` |
| `upstream-unavailable` | 502 / 503 | GBIF or raster provider down during a synchronous call (species search) |
| `shutting-down` | 503 | server draining; `Retry-After` |

Job failures are reported inside the job resource (`error` = problem object), not as HTTP errors on
`GET /jobs/{id}`.

### 2.4 Versioning policy

- Major version in the URI. Within v1 only additive, backward-compatible changes: new endpoints,
  optional request fields with defaults that preserve previous behaviour, new response fields, new
  enum values in *output* fields documented as open (`state` is closed; `event.type`,
  `artifact.role`, `problem.code` are open), new SSE event types.
- Changing a scientific default (e.g. default regularisation) is treated as breaking for
  reproducibility: it requires a new `engine_version` and is recorded in manifests; old jobs keep
  their manifest. The API itself stays v1 [REC].
- Breaking changes → `/api/v2`, with v1 kept for ≥ 1 minor release; deprecated operations send
  `Deprecation` and `Sunset` headers [UNVERIFIED – prior knowledge: RFC 9745, RFC 8594].
- CI diffs the generated OpenAPI against the committed one and fails on breaking changes.

## 4. Endpoints

### 4.1 POST /api/v1/jobs

Request (`JobSpec`):

```json
{
  "kind": "sdm.maxent",
  "label": "Lutra lutra — Occitanie 2026",
  "species": [{ "taxon_key": 5219073, "name": "Lutra lutra" }],
  "study_area_id": "0192f3a4-0000-7000-8000-000000000001",
  "occurrences": {
    "source": "gbif",
    "filters": { "year_min": 2000, "coordinate_uncertainty_max_m": 1000, "basis_of_record": ["HUMAN_OBSERVATION","PRESERVED_SPECIMEN"] },
    "dataset_id": null,
    "thinning": { "method": "grid", "cell_size_m": 1000 }
  },
  "environment": {
    "dataset_id": "0192f3a4-0000-7000-8000-0000000000e1",
    "layers": ["bio1","bio4","bio12","bio15"],
    "resolution": 1000,
    "crs": "EPSG:2154"
  },
  "background": { "n_points": 10000, "strategy": "random" },
  "model": {
    "maxent": {
      "feature_classes": ["linear","quadratic","hinge"],
      "regularization_multiplier": 1.0,
      "max_iterations": 500,
      "convergence_threshold": 1e-5,
      "output": "cloglog"
    }
  },
  "validation": { "scheme": "spatial_block", "k": 5, "block_size_m": 50000 },
  "outputs": { "thresholds": ["max_sss","p10"], "rasters": ["suitability","binary","uncertainty"] },
  "seed": 42,
  "priority": "normal",
  "reuse": "never"
}
```

| Field | Type | Req | Notes |
|---|---|---|---|
| `kind` | enum `sdm.maxent` | yes | open for future algorithms |
| `species` | array 1..1 of `{taxon_key:int, name?:string}` | yes | one species per job; use batches for N |
| `study_area_id` | uuid | yes | |
| `occurrences.source` | `gbif` \| `dataset` | yes | `dataset` requires `dataset_id` |
| `environment.layers` | string[] 1..64 | yes | must exist in dataset |
| `model.maxent.*` | see the MaxEnt research document | no | defaults applied server-side and echoed in `effective_spec` |
| `validation.scheme` | `random_kfold` \| `spatial_block` \| `none` | no | default `spatial_block` |

Implemented `ValidationSettings` (`dto.rs`): `method` `spatial_block` (default) \| `spatial_grid` \|
`random_kfold`; `folds` (default 5 for `spatial_grid`, 4 otherwise); opt-in (ADR-0014, omitted from
the JSON when off): `block_km` (`spatial_grid` only, 1–1000 km, absent = automatic),
`null_models` (0 or 19–200), `aoa` (bool). Results add `validation.blocks`,
`validation.null_model`, `aoa`; the tile layer `aoa` and the sample field `aoa_di` exist when
`aoa.tif` was written.
Bias and cleaning options (ADR-0011, ADR-0013; omitted from the JSON when off):
`filters.thin_km` (0 < x ≤ 100 km), `model.background_method` `random` (default) \|
`target_group`, `model.target_group` (GBIF class, `target_group` only; absent = the species'
class); `DataPreviewRequest.seed` (thinning in the preview). Results add `data.generalised`
(real data), `background_sampling` and `sampling_bias` (target group requested); occurrence
statuses `generalised` and `thinned`; the tile layer `effort` and the sample field `effort` exist
when `effort.tif` was written. Warnings: `generalised_records`, `generalisation_flags_unavailable`,
`target_group_unavailable`, `target_group_background_smaller`, `effort_concentration`.
Second engine (ADR-0017; omitted from the JSON when MaxEnt / default / off): `model.algorithm`
`maxent` (default) \| `rf` \| `ensemble`, `model.rf_trees` (100–2000, absent = 500),
`model.rf_tune_mtry` (bool); the `rf_*` fields are refused (400) with `maxent`. Results add
`selected.algorithm`/`rf_trees`/`rf_mtry`/`rf_seed`, `tuning[].algorithm`/`mtry` (RF rows),
`validation.members` (ensemble), `contributions[].rf_importance`, `partial_dependence`; files
`model.rf.json` and `partial_dependence.csv`. Results written before these fields still load.
Future-climate projections (ADR-0016; omitted from the JSON when empty): `projections[]` of
`{period, ssp, gcms[]}` with `period` ∈ `2011-2040` \| `2041-2070` \| `2071-2100`, `ssp` ∈
`ssp126` \| `ssp370` \| `ssp585`, `gcms` ⊆ the five ISIMIP3b models (non-empty, no repeats); no
repeated (period, ssp); at most 15 scenario × GCM runs per study; at least one climate layer
selected (400 otherwise). Results add `projections[]` (`ProjectionResult`: threshold, climate and
static variables, cells and missing cells, present/future suitable km², stable/gained/lost/
unsuitable km² and the part on which every GCM agrees, mean SD across GCMs, novel fraction,
`per_gcm[]`, `synthetic`); files `future_<period>_<ssp>_{mean,sd,change,agreement,mess}.tif` and
`future_areas.csv`; tile layers `future_<period>_<ssp>_{mean,sd,change,mess}` (the change layer is
pale where fewer than a majority of GCMs agree; other names → 404); the sample adds
`projections[]` (`period`, `ssp`, `gcms`, `mean`, `sd`, `change` 1–4, `agreement`, `mess`).
Warnings: `static_predictors_in_projection`, `projection_without_climate`,
`projection_extrapolation`, `projection_missing_cells`, `projection_not_computed`.
| `seed` | u64 | no | generated if absent; always echoed |
| `priority` | `low` \| `normal` \| `high` | no | |
| `reuse` | `never` \| `if_identical` | no | default `never` |

Responses:
- `201 Created`, `Location: /api/v1/jobs/{id}`, body = `Job` (§4.2) in state `queued`.
- `200 OK` + `Content-Location` when `reuse=if_identical` matched.
- `400`, `404` (study area/dataset), `413`, `415`, `422` (`validation-failed`,
  `resource-limit-exceeded`, `idempotency-key-reused`), `409` (idempotency in progress), `503`
  (`shutting-down`).

`state` (closed enum): `queued`, `preparing`, `running`, `finalizing`, `cancelling`, `succeeded`,
`failed`, `cancelled`. Terminal: `succeeded`, `failed`, `cancelled`. `error` (when `failed`) is a
problem object with job-specific codes: `insufficient-occurrences`, `no-environment-coverage`,
`optimizer-diverged`, `upstream-unavailable`, `resource-exhausted`, `internal`, plus
`retryable: bool`.

Supports `ETag` (derived from `last_event_id` + state) and `If-None-Match` → `304` for cheap
polling.

### 4.3 GET /api/v1/jobs/{id}/events (SSE)

Request headers: `Accept: text/event-stream`; optional `Last-Event-ID: <seq>`. Non-browser clients MAY
use `?after=<seq>` (same meaning). `?types=progress,state` filters (default all).

Wire format (one event):

```
id: 319
event: progress
data: {"job_id":"0192f3a5-…","seq":319,"ts":"2026-10-15T09:13:10.500Z","fraction":0.43,"step":"train.fold.3","message":"Fold 3/5: iteration 230"}

```

Behaviour:
- First event carries `retry: 3000`. Comment keep-alive (`: keep-alive`) every 15 s [18].
- Server replays persisted events with `seq > Last-Event-ID`, then streams live. `id` = `seq` (per-job
  monotonic integer).
- `progress` events are coalesced (≤ 4/s) and only the latest is guaranteed on replay; all other
  types are always persisted and replayed.
- After `job.finished` the server closes the stream. Reconnect to a terminal job with
  `Last-Event-ID ≥ last seq` → `204 No Content` (stops `EventSource` reconnecting [18]).
- `404` unknown job; `406` if `text/event-stream` not acceptable.
- Response headers: `Cache-Control: no-cache`, `X-Accel-Buffering: no`; never compressed.

Event types (`event:` field; payload always includes `job_id`, `seq`, `ts`):

| type | Persisted | Payload (in addition to common) |
|---|---|---|
| `job.state` | yes | `from`, `to`, `reason?` |
| `step.started` | yes | `step`, `index`, `total` |
| `step.finished` | yes | `step`, `duration_ms`, `cached: bool`, `output_artifacts[]` |
| `step.retrying` | yes | `step`, `attempt`, `delay_ms`, `error` (problem) |
| `progress` | latest only | `fraction` 0..1, `step`, `message`, `iteration?`, `loss?` |
| `metric` | yes | `name` (e.g. `auc_test`, `cbi`), `value`, `fold?` |
| `artifact.created` | yes | `artifact_id`, `role`, `media_type`, `size` |
| `log` | yes | `level` (`info`\|`warn`), `message` |
| `warning` | yes | `code`, `detail` |
| `job.recovered` | yes | `previous_boot_id`, `resumed_from_step` |
| `job.finished` | yes | `state` (terminal), `error?`, `results_url` |

Batch stream (`/batches/{id}/events`) emits `batch.progress` (`jobs_by_state`, `fraction`),
`batch.job_state` (`job_id`, `to`) and `batch.finished`; its `id` is a per-batch sequence.

### 4.4a GET /api/v1/jobs/{id}/gbif-wait, POST /api/v1/jobs/{id}/skip-download (implemented 2026-10-19)

`gbif-wait` → `GbifWait` or `null`: `key`, `status` (`requesting`, GBIF's `preparing`/`running`…,
`downloading`), `since`, `checked_at` (last poll, every 10 s), `url` (gbif.org page),
`slow_after_s` (1200), `skip_after_s` (1800), `search_api_max_records`. `skip-download` → `204`;
`409` unless the job is queued, preparing its download and has waited `skip_after_s`. Only the
owning organisation (no support access). See job-lifecycle.md.

### 4.4 POST /api/v1/jobs/{id}/cancel

No body. Responses:
- `202 Accepted` + `Job` in `cancelling` (running) or `cancelled` (was queued).
- `200 OK` + `Job` if already `cancelling`/terminal (idempotent; no error for already-finished).
- `404` unknown.

### 4.5 POST /api/v1/jobs/{id}/retry

Allowed from `failed` or `cancelled`. Creates a new job with the same `effective_spec` (and same seed
unless body `{ "new_seed": true }`); memoised steps are reused. `201` + `Location`; `409
conflict-state` otherwise.

### 4.8 GET /api/v1/species/search

Query: `q` (≥ 2 chars, required), `rank` (default `SPECIES`), `limit` (1..50, default 20),
`lang` (`fr`, `en`, `la`; vernacular names), `country` (ISO 3166-1 alpha-2, optional, for
occurrence count hint).

```json
{
  "items": [
    { "taxon_key": 5219073, "scientific_name": "Lutra lutra (Linnaeus, 1758)", "canonical_name": "Lutra lutra",
      "rank": "SPECIES", "status": "ACCEPTED", "vernacular_names": { "fr": "Loutre d'Europe" },
      "kingdom": "Animalia", "class": "Mammalia", "family": "Mustelidae",
      "source": "gbif-backbone", "occurrence_count_hint": null }
  ],
  "next_cursor": null

```

Synchronous proxy to the taxonomy provider with a local cache (TTL 7 d). `502/503
upstream-unavailable` when the provider fails and no cached answer exists; response header

### 4.9 Datasets

`Dataset`:

```json
{
  "id": "0192f3a4-…",
  "kind": "environment",
  "name": "WorldClim 2.1 bioclim 30s",
  "provider": "worldclim",
  "version": "2.1",
  "licence": "…",
  "citation": "…",
  "crs": "EPSG:4326",
  "resolution": 0.008333,
  "extent": [-180, -90, 180, 90],
  "layers": [{ "name": "bio1", "unit": "°C", "description": "Annual mean temperature", "dtype": "float32", "nodata": -3.4e38 }],
  "status": "available",
  "local_size_bytes": 0,
  "cached": false
}
```

- `kind`: `environment` | `occurrences`. `status`: `available` | `downloading` | `error`.
- `POST /datasets` (multipart): `metadata` (JSON part: `kind`, `name`, `crs?`, `licence`) + `file`
  parts (GeoTIFF/COG for environment; CSV with `lon,lat[,species]` columns + `crs` for
  occurrences). Returns `201` with `status: "available"` after validation, or `202` +
  `{ "job_id" }` if ingestion (hashing, COG conversion) runs as a job.
- Remote catalogue datasets are downloaded lazily as steps of a job; `POST
  /datasets/{id}/prefetch` → `202 { job_id }` optional.

**Implemented 2026-10-20 (ADR-0108): the organisation's occurrence datasets.** The design above
(multipart, environment datasets) is not implemented; what exists is narrower and JSON-only (the
CSRF guard requires JSON bodies; the 8 MB limit applies):

| Method | Route | Effect |
|---|---|---|
| GET | `/api/v1/datasets` | `DatasetInfo[]` of the caller's organisation (local mode: datasets without organisation), newest first; never records |
| POST | `/api/v1/datasets` | `ImportRequest` (name, file name, `file_sha256` computed in the browser, `crs` from the closed list, `columns` = one string array per chosen column: `taxon`, `x`, `y`, optional `date`, `uncertainty`, `status`, `survey`; `lines`; `absent_values`; `mapping`) → `201 DatasetInfo` with the import report; `422` when no row is usable or the request is malformed (messages never quote a cell); `409` beyond 20 datasets per organisation |
| GET | `/api/v1/datasets/{id}` | `DatasetInfo`; `404` for another organisation's |
| DELETE | `/api/v1/datasets/{id}` | `204`; studies already submitted keep their copy |
| GET | `/api/v1/coordinate-systems` | closed list `CrsOption[]` (`EPSG:4326`, `2154`, `3035`, `25828–25831`, `32628–32632`) |
| POST | `/api/v1/species/match` | `{names}` (≤ 200) → `TaxonMatch[]` from GBIF's name matcher; only names are sent; `accepted` = exact match at species rank or below |

Studies: `JobSpec.own_dataset = {id, records_sha256}` and `SpeciesRef.own = {values, role:
"training"|"validation", gbif}` (both omitted by default; ADR-0108 §3). `POST /jobs` answers `404`
when the dataset is not the caller's organisation's, `409` when its checksum changed, `422` for
inconsistent use. `POST /occurrences/preview` accepts the same `own_dataset` + `own` and answers
`by_source` and `validation_sites`. Results add `data.by_source`, `independent_validation`, the
evidence level `validated`, and `OccurrencePoint.source` (`gbif`/`own`) when the organisation's data
are used.

### 4.10 Study areas

`POST /study-areas` body — exactly one of:

```json
{ "name": "Occitanie", "geometry": { "type": "MultiPolygon", "coordinates": [] } }
{ "name": "Box", "bbox": [1.2, 42.3, 4.9, 45.0] }
{ "name": "Hérault", "admin_unit": { "source": "insee", "code": "34", "level": "department" } }
```

Optional: `buffer_m`, `working_crs` (default chosen per region, e.g. EPSG:2154 for metropolitan
France [ASSUMPTION]). Response `StudyArea`: `id`, `name`, `geometry_hash`, `bbox`, `area_km2`,
`working_crs`, `created_at`, `geometry_url` (`/api/v1/study-areas/{id}?format=geojson`).
Validation errors: invalid/self-intersecting geometry, area outside dataset coverage, too many
vertices (> 100 000) → `422`. `DELETE` → `409 conflict-state` if referenced by jobs.

**Implemented (2026-10-16, ADR-0012): places from self-hosted boundary packs.** The job's
`study_area` stays inline (`name`, `geometry`); when built from administrative units it also
carries `places: [{ id, name, pack, attribution }]`.

- `GET /api/v1/places?q=gironde&country=FR&limit=10` → `PlaceHit[]`: `id` (`FR-D33`, `ES-3401`,
  `FR-C33063`, `FR-PFR8000001` park, `ES-NES0000024` Natura 2000…), `name`, `level`
  (`country|region|department|intercommunality|municipality|protected`), `designation` (protected
  areas: "Parc naturel régional", "Parque Nacional", "Natura 2000 · ZPS"…),
  `country`, `within` (ancestor names, nearest first), `bbox`, `area_km2`, `pack`, `attribution`.
- `GET /api/v1/places/at?lng=&lat=` → every unit containing the point, country first.
- `GET /api/v1/places/{id}` → `PlaceGeometry`: `place` (a `PlaceHit`) and its GeoJSON
  `geometry` (MultiPolygon); unknown id → `404`.
- `GET /api/v1/health` lists the installed packs in `boundaries`.
- `POST /api/v1/study-areas/check` `{ "area": StudyArea }` → `AreaCheck`: `max_cells` (deployment
  limit within the hard cap) and `resolutions: [{ factor, cells, fits }]` for the factors the UI
  offers (1, 2, 5, 10). Cells are counted over the area's bounding box, as job validation does.

**Warnings** (`Warning`: `code`, `severity`, `message`) also carry `params` (e.g.
`{ "n": 840 }` for `non_commercial`) so that interfaces word known codes in their language;
`message` stays in English for reports, logs and older clients.

### 4.11 Batches

```json
POST /api/v1/batches
{
  "label": "ZNIEFF mammals 2026",
  "species": [{ "taxon_key": 5219073 }, { "taxon_key": 2440940 }],
  "template": { "...": "JobSpec without species" },
  "max_parallel": null
}
```

`201` → `Batch { id, label, job_ids[], counts: {queued, running, succeeded, failed, cancelled},
state: "active"|"finished", created_at, links }`. Up to 1 000 species per batch [ASSUMPTION,
configurable]; jobs are created atomically (all or none). `GET /batches/{id}/results` returns a
summary table (one row per species: state, `auc_test.mean`, `suitable_area_km2` per threshold,
artifact ids); `?format=csv` supported.

### 4.12 Artifacts and tiles

- `GET /artifacts/{artifact_id}`: content-addressed, therefore `ETag: "<hash>"` and
  `Cache-Control: public, max-age=31536000, immutable`; supports `Range` (COG streaming) → `206`;
  `Content-Disposition` with a human filename via `?filename=`. `410 gone` after GC.
- `GET /artifacts/{id}/tilejson` → TileJSON 3.0 [UNVERIFIED – prior knowledge] with `tiles`,
  `bounds`, `minzoom`, `maxzoom`.
- `GET /artifacts/{id}/tiles/{z}/{x}/{y}.png?style=viridis&min=0&max=1`: Web Mercator XYZ tiles
  rendered on demand from the COG and cached (derived data); `204` for empty tiles.
- Raw-value probing: `GET /artifacts/{id}/value?lon=&lat=` → `{ "value": 0.73, "crs": "EPSG:2154" }`.

### 4.13 Health and version

`GET /health`:

### 4.13a Organisation managers and administration additions (implemented 2026-10-19, ADR-0109)

Managers (`Me.is_manager`), their own organisation only — `403` for other members, `404` for
accounts or invitations of other organisations, `409` on their own account, `403` on an NS
administrator: `GET /org/members` (`UserInfo[]`), `GET|POST /org/invites` (`InviteInfo[]` |
`201 LinkCreated`), `POST /org/invites/{id}/revoke`, `POST /org/members/reset {email}`
(`201 LinkCreated`), `POST /org/members/disable {email, disabled}`.

Administrators: `GET /admin/system` → `SystemStatus` (version, build, started_at, disk,
storage sizes, job counts, packs, database copies, `volume_backup`, GBIF account check,
retention); `GET /admin/metrics?month=YYYY-MM` → `OrgMetrics[]`; `POST /admin/users/manager
{email, manager}` → `204`; `POST /admin/users/admin {email, password}` → `204` (ADR-0112: the
requesting administrator's own password; `403` wrong password, `409` account outside the operator
organisation or none designated, `429` after repeated wrong passwords; removal is CLI only).
`GET /admin/users?org=&q=&offset=&limit=` → `UserPage {users, total, next_offset}` (ADR-0113; 100

`GET /org/audit?before=&limit=` → `AuditPage` (managers: their organisation's history).
`GET /admin/audit?org=&user=&before=&limit=` → `AuditPage {entries: AuditEntry[], next}` (ADR-0113:
newest first, keyset pages of 50 by default, at most 200; `user` matches changes to or by the
account; names are the current ones, `null` once erased). `Org.is_operator`, `UserInfo.in_operator_org`; `PATCH /admin/orgs/{id} {disabled: true}` on the
operator organisation → `409`. `UserInfo.is_manager`; `ActivityRow.cause` (failed studies) and
`ActivityRow.gbif_wait` (queued studies waiting for GBIF).

### 4.13c Regional GBIF mirror (implemented 2026-10-19, ADR-0114)

`AreaCheck.gbif_mirror` (`POST /study-areas/check`): the date (YYYY-MM-DD) of the regional mirror
that serves the area's records without waiting for GBIF; absent otherwise. `SystemStatus.gbif_mirror`
(`GET /admin/system`): `MirrorStatus` — region, state (`ready`, `requesting`, `waiting`,
`downloading`, `building`, `error`, `disabled`), the snapshot in use (download key, DOI, date,

The manifest's `occurrence_source` gains `mirror` (snapshot and records per dataset) and
`gbif_account: "mirror"` for studies it served.

### 4.13b Account and organisation properties, GBIF accounts (implemented 2026-10-19, ADR-0110)

Hosted mode only (`404` in local mode). Every signed-in account: `PATCH /account {name}` → `204`;
`POST /account/password {current, new}` → `204` (`422` if `current` is wrong; the other sessions
are closed, this one stays); `GET /account/gbif` → `GbifSettings` (`own`, `organisation`,
`shared`, `effective` = `user|organisation|shared|none`, `can_store`); `PUT /account/gbif

`POST /account/gbif/check` → `GbifAccountInfo` (asks GBIF, remembers `ok`); `DELETE

### 4.13c Feedback (implemented 2026-10-19, ADR-0111)

Hosted mode only (`404` in local mode). Every signed-in account: `POST /feedback
{kind?, message?, page?, context?, attachments?: [{name, mime, data (base64)}]}` → `201 {id}`
(`422` without message nor attachment, over 10 000 characters, 6 attachments or 12 MB, or with a
type other than PNG/JPEG/WebP/GIF images and WebM/Ogg/MP4/MPEG/WAV audio). `GET
/feedback/{id}/files/{file}` → the attachment, `Content-Security-Policy: sandbox` (author, their

Forwarding to the operator's issue tracker is a deployment setting and has no API surface.

## 5. Alternatives

- WebSocket instead of SSE: rejected (no client→server messages needed; SSE has native resume).
- Header/media-type versioning: rejected for discoverability in browser devtools; URI versioning is
  simpler for a single-binary product.
- Offset pagination: rejected (unstable with concurrent inserts; costly counts).
- GraphQL: rejected (job/resource model is simple; caching of immutable artifacts via HTTP is a
  strength of REST).

## 6. Trade-offs

- Rejecting unknown request fields catches parameter typos (scientific safety) at the cost of
  stricter forward-compatibility for clients sending newer fields to older servers.
- Coalesced `progress` events reduce DB load but replay is not a complete iteration log.
- One species per job keeps jobs small, resumable and memory-predictable; batches add an aggregate
  resource.

## 7. Risks

- Tile rendering on demand can compete with jobs for CPU → render on the rayon pool with a separate
  small semaphore; cache aggressively.
- Large GeoJSON study areas inflate request size → 10 MiB limit + server-side simplification
  warnings.
- Expired Idempotency-Key draft may change; behaviour documented here is our contract.

## 8. Recommendations

- [REC] Implement handlers with utoipa annotations from the start; serve `/api/v1/openapi.json` and a
  docs UI (`utoipa-scalar` or `utoipa-swagger-ui`) behind a feature flag.
- [REC] Generate TypeScript client types from OpenAPI for the frontend.
- [REC] Contract tests: replay SSE with `Last-Event-ID`, idempotency 409/422 paths, cancel races.

# NicheRS — System architecture

Status: v0.1 (2026-10-15). Synthesises the Phase 0 research; decisions are recorded as ADRs in
`architecture-decisions/`. Where this document and an ADR disagree, the ADR wins.

## 1. What changed from the initial proposal

The proposal (Rust scientific engine + Rust geo engine + Axum server + React + optional WASM) mostly
holds. Research changed these points:

| Initial proposal | Decision | Why |
|---|---|---|
| "Rewrite MaxEnt" | Path-faithful port of maxent.jar 3.4.4, validated by golden tests (ADR-0001) | Matching the objective is not enough: the jar stops after damped greedy steps; generic solvers land elsewhere. Gate G1 passed: 11/11 cases. |
| Rust geo engine handles "everything" | Pure-Rust core with an explicit format/CRS allow-list; GDAL optional feature (ADR-0003) | No pure-Rust GDAL replacement is mature; restricted inputs make the single binary honest. |
| WASM module | Not in MVP (ADR-0005) | No measured browser-side need. |
| One monolithic job worker | In-process bounded Rayon pool + cooperative cancellation; same-binary subprocess worker later (ADR-0103) | Crash/memory isolation only needed once native C libraries or multi-user servers are involved. |
| WorldClim as default climate | CHELSA v2.1 (CC0) (ADR-0006) | WorldClim forbids commercial use/redistribution without permission. |
| "Confidence" score | Separate indicators + rule-based evidence level, no percentage (ADR-0007) | Presence-background data cannot support a probability or a single confidence number. |

## 3. Data flow of a single-species run

1. **Define**: species (GBIF/TAXREF key pinned), study area (GeoJSON/GPKG, validated, reprojected to
   the modelling grid CRS, default EPSG:3035), resolution, predictor set from the catalogue.
2. **Ingest** (`data-pipeline.md`): occurrences with provenance (download DOI/query hash, licence per
   record), cleaning with recorded exclusion reasons, cell-level de-duplication/thinning.
3. **Prepare**: environmental stack aligned to the modelling grid (resampling by layer type),
   background sample (seeded), SWD matrices. Cached by content hash, shared across species.
4. **Train/tune**: `niche-maxent` per (feature classes × β) × spatial folds on a Rayon pool;
   cancellation polled every iteration.
5. **Evaluate**: Boyce, omission@P10, AUC(PB, secondary), fold spread, MESS/AOA.
6. **Predict**: tiled raster inference with clamping; COG output + STAC item; suitable-area band.
7. **Record**: execution manifest (inputs, hashes, versions, seeds, settings, metrics).

## 4. Execution model

- Tokio handles HTTP/SSE/file I/O; CPU work goes to a dedicated Rayon pool sized by
  `NICHE_MAX_WORKERS`; a memory semaphore (`NICHE_MAX_MEMORY_MB`) admits jobs by estimated
  footprint. Never `spawn_blocking` for numerics.
- Parallelism is across fits/folds/species and raster tiles, not inside one optimizer (the MaxEnt
  path depends on sequential floating-point order; see ADR-0001).
- Job state machine and recovery: `job-lifecycle.md`. Durability: ADR-0008.

## 5. Interfaces and versioned formats

| Interface | Format / version | Owner doc |
|---|---|---|
| REST API | `/api/v1`, OpenAPI 3.1 generated by utoipa, snapshot-tested | `api-design.md`, ADR-0202 |
| Model file | MaxEnt `.lambdas` (3.4.4 grammar) + JSON sidecar (schema v1: variables, types, settings, engine version) | `mathematical-specification.md` |
| Execution manifest | JSON schema v1 | `execution-manifest.md` |
| Rasters | COG (GeoTIFF 1.1), float32, explicit NoData; STAC 1.1.0 item | ADR-0204 |
| Vectors | GeoJSON (RFC 7946), GeoPackage import | ADR-0204 |
| Config | CLI flag > env `NICHE_*` > TOML file > defaults | `configuration.md`, ADR-0101 |

## 6. Deployment modes

Local (loopback, per-launch token, embedded UI), Server (reverse proxy, auth required, limits),
Batch (headless CLI). Same engine, config semantics, model formats. See `deployment-modes.md`.

## 7. Separation of concerns

| Concern | Where it is guaranteed |
|---|---|
| Scientific correctness | `niche-maxent` golden tests; `mathematical-specification.md`; `07-scientific-validation.md` |
| Computational performance | `docs/benchmarks/`; stage benchmarks B0–B7 |
| User experience | `docs/design/`, `ux-specification.md` |
| Operational simplicity | single binary, `twelve-factor-compliance.md`, `observability.md` |
| Extensibility | hexagonal boundaries (ADR-0201), versioned formats above |
